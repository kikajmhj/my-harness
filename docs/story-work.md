# 허들링 앱 — 수작업 디자인 프로세스 (AI 없이)

> 이 문서는 "내가 실제로 어떻게 했는지"의 기록입니다.
> "무엇을 위한 일인지"는 `story-service.md`를 참고하세요.

## 원문 (작업자 진술)

1. 나는 uibowl에서 경쟁사 레퍼런스를 수집한다.
2. 레퍼런스를 토대로 분석하고 우리 서비스에 반영할 부분을 가져온다.
3. 분석 내용을 토대로 우리 서비스 화면 설계 문서를 구체화한다.
4. Figma에 레퍼런스와 화면설계서를 반영한 UI 키스크린 2~3개를 390×844 사이즈로 그린다.
5. 내부 관계자들과 협의 후 컨셉 시안을 확정한다.
6. 컨펌된 시안을 기반으로 디자인 토큰과 컴포넌트를 제작하고, 화면 디자인에 들어간다.
7. 완성된 시안에서 토큰이나 컴포넌트가 우리 가이드에 위반된 부분이 없는지 검토한다.

## 결정 사항과 근거

| 항목 | 결정 | 근거 |
|---|---|---|
| G1 컨펌 주체 | 본인(작업자) | 1번은 경계 없음으로 지정됨 → 외부로 넘기지 않고 작업자가 멈춰서 확인 |
| G2, G3 | 필수 게이트 | 작업자 지정: 레퍼런스 분석 / 화면 설계 / 디자인 제작 사이에 반드시 게이트 |
| G3 위치 | 3번 → 4번 사이 | 4번이 첫 디자인 작업이므로 설계 확정 후 그려야 재작업이 줄어듦 |
| 5번 | 게이트(G4) + 경계 | 사람에게 넘기는 합의 단계이며, 확정 전에는 6번 진행 불가 |
| 1, 3, 6번 경계 | 없음 | 작업자 지정 |
| 2번 경계 | 없음 | 1~3번은 같은 작업자가 이어서 진행 |
| 7번 경계 | 별도 검토자 | 만든 쪽의 자체 검토는 위반을 놓치기 쉬움 |
| 7번 "우리 가이드" | `design.md` | PRD §14, §15에서 토큰·컴포넌트 기준 문서로 지정 |
